# Build and test a JCB extension in Playground

Open an agent-owned site with `workspace_open({"deployId":"jcb-mcp"})` or attach to the intended client workspace. Read `joomengine://skills/workflows/request-to-extension.md` and `joomengine://skills/testing/playground/README.md`. They cover field and view selection, GUID relationships, Powers, source authoring, installation, runtime testing and delivery.

1. Use `native_tools` and `native_call` to find the registered actions on this installation. Search and describe the action before using it. Joomla applies its normal permissions and write plans. For tasks handled by a Joomla administrator form, the browser navigation and editing tools work against the same site. For repeatable deployments, Playground also accepts native JCB record overlays in the deployment configuration.
2. Run `jcb_list_components`. Use the returned ID for `jcb_compile`. The compiler submits its own administrator form with the current CSRF token. It returns the actual generated component, plugin and module installer paths with sizes and SHA-256 hashes. A compile can take several minutes. After a disconnected call, inspect the compiler page and its files before submitting again.
3. Pass each wanted installer path to `file_export`. Read its bytes with successive `artifact_read` calls, following `nextOffset` until it is null. Check its total size and SHA-256. `extension_install` accepts the returned artifact ID or a remote HTTPS installer URL. Deliver the actual compiled installer to the user.
4. Open the generated Joomla screens. Exercise the component's requirements with realistic records, including relevant error cases. For published APIs, install the **linked webservices plugin** generated with the component, enable it using `extension_enable_plugin`, and call `jcb_refresh_tools`. The native MCP now discovers the registered routes the authenticated Joomla user can access. Search by component in `joomla_actions_search`, describe the returned action and perform the read using the discovered ID.
5. Return to the maintained JCB definition for lasting corrections. Recompile and rerun the checks. Use `site_export({"format":"bundle"})` when delivering the full site. Verify the package and generated API again after restoring into an agent-owned runtime with `site_restore`. Complete-site archives can contain private Joomla credentials.

The repository's `node test/jcb-live.mjs` acceptance scenario runs the actual stdio client, reads the packaged skill, changes the seeded Demo J6 definition through its Joomla model, compiles the new version, verifies the transferred ZIPs, installs the component and webservices plugin, reads a country through the generated API and checks that same record after a complete-site restore. The script writes only to a fresh browser workspace. A green run covers this specific extension graph and route. Additional applications should supply their own acceptance cases and expected data.
