# Operating Playground development tools

Every tool below addresses the active workspace in the current MCP connection. Attached clients operate on the same files, database and browser profile as the person using Playground. Use `workspace_info` to inspect the workspace ID, persistence, recovery mode and current debugger state.

| Playground control | Agent workflow |
| --- | --- |
| JoomEngine Code | Browse with `file_list`, inspect files or directories using `file_stat`, and follow `nextOffset` through `file_read`. Use `file_search` for filename, text or whole-word searches, include/exclude globs and case sensitivity. Use the returned cursor for the next page or `file_search_cancel` to finish early. |
| Save, upload, move, copy and undo edits | Pass the observed revision to `file_write` or `file_import` and null for a new path. Import binary files using `artifact_load` followed by `file_import`. Use `file_manage` for directory creation, copying, renaming, deletion and undo. `file_batch` submits one revision-checked sequence of editor operations, with one recovery ID. A partial failure includes the applied results, failed index and recovery ID. Inspect `file_history` to find this worker's recent snapshots before calling `file_manage` with action `recover`. |
| Database viewer/editor | `database_query` binds positional SQL parameters to the live MariaDB database and returns its Joomla table prefix. Bind binary data using an object containing `base64`; request `binaryColumns` to receive exact bytes in selected fields. Large integers return as decimal strings. Query results report truncation. Use SQL pagination for further rows and SQL substring reads for a large value. |
| Adminer import, export and forms | Call `database_open`, then `browser_navigate` to its returned path. For a SQL script, append `?import=`, load its file artifact, and use `browser_upload` on `#form input[type=file]` with `artifactIds` containing the artifact ID. Submit the displayed form, inspect the result and read the affected data. Adminer uses the current site’s own database and authenticated form token. `site_export` with format `database` returns a portable SQL dump. |
| PHP debugger | `debug_control` sets breakpoints, starts a real request, pauses, steps, continues, evaluates expressions and reads stack frames, scopes and variables. Variable reads support `start` and `count`. `state` includes runtime capabilities and request completion or error. |
| Mail catcher | `mail_list` and `mail_get` read the current session inbox, text and HTML bodies, MIME headers, envelope and attachment metadata. Download the original message, including attachments, with `mail_get` format `raw`. `mail_clear` clears the session inbox. |
| Cache, persistence and recovery | Use `workspace_cache_clear` to clear Joomla caches and `workspace_flush` to save pending persistent changes. In a damaged saved site, inspect `workspace_info.recovery`; use `workspace_recovery_export` to preserve the filesystem, including when the database is unavailable. `workspace_repair` invokes Playground’s configuration repair and preserves an original configuration backup; restart the site after repair. |
| Named backups | `backup_save` creates a complete snapshot. `backup_list` returns revision numbers and a storage estimate. `backup_update` takes the selected ID and its expected revision, preserves the backup ID and creation time, and can set a new name. `backup_delete` requires that same revision so a stale request cannot delete a newer snapshot. |
| Complete sites and transfer | `backup_export` returns an archive artifact; `artifact_save` downloads that artifact into the configured host directory. To preserve an uploaded site as a backup, load the ZIP with `artifact_load` and pass the artifact ID to `backup_import`. To run it, use `site_restore`. `site_export` supports complete, files-only and SQL downloads as well as target database connection overrides accepted by the native exporter. Portable archives and SQL data can contain private site credentials. |
| Backups panel storage management | `storage_list` returns the owner’s inventory of stored sites, runtime files, images, custom deployments and preferences. Inspect the specific ID and its protection flags before `storage_remove`. The owner rechecks live protection and uses the same cleanup functions as its panel. Removing an unassigned store requires selecting its exact ID and setting `allowUnassigned`. |
