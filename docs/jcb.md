# Build and test a JCB extension in Playground

Open an agent-owned site with `workspace_open({"deployId":"jcb-mcp"})` or attach to the intended client workspace. Read `joomengine://skills/workflows/request-to-extension.md` and `joomengine://skills/testing/playground/README.md`. They cover field and view selection, GUID relationships, Powers, source authoring, installation, runtime testing and delivery.

1. Use `native_tools` and `native_call` to find the registered actions on this installation. Search and describe the action before using it. Joomla applies its normal permissions and write plans. For tasks handled by a Joomla administrator form, the browser navigation and editing tools work against the same site. Before authoring, call `jcb_form` with the native JCB view, such as `{"view":"field","fields":["fieldtype","datatype"]}`. Omit `fields` to read the full installed form schema, including available defaults, required fields, choices and linked-record metadata. For a new record, pass candidate source fields in `values` to run native validation and inspect the form after conditional fields have been resolved. The response includes `validation.valid` and the native error message for an incomplete candidate. This inspection does not save the record. Joomla’s portable schema omits hidden controls, including the field designer’s serialized `xml`; refer to the packaged JCB field-authoring guidance for this value. Submit JCB source records through `jcb_save_records`. Playground validates them with native Joomla forms and JCB models. A partially applied batch returns an MCP tool error with every record’s key, status and any saved identity in `structuredContent.results`. Read back the applied records, correct the skipped ones and resubmit only those keys.
2. Run `jcb_list_components`. Use the returned ID for `jcb_compile`. The compiler submits its own administrator form with the current CSRF token. `jcb_list_components` also reports the installed compiler’s `compilerOptions`, including field names, current values and choices. Pass only the overrides you want in `jcb_compile.options`. Use strings for scalar controls and arrays of values for checkboxes or multiple-selection controls. For the Skills compiler-tracing workflow, select the offered “Yes” values for `add_placeholders` and `debug_line_nr`, compile and install, then search generated files for the probe. Omitting overrides on the next compilation uses the native form defaults. It returns the actual generated component, plugin and module installer paths with sizes and SHA-256 hashes. A compile can take several minutes. After a disconnected call, inspect the compiler page and its files before submitting again.
3. Pass each wanted installer path to `file_export`. Read its bytes with successive `artifact_read` calls, following `nextOffset` until it is null. Check its total size and SHA-256. `extension_install` accepts the returned artifact ID or a remote HTTP(S) installer URL. Deliver the actual compiled installer to the user.
4. Open the generated Joomla screens. Exercise the component's requirements with realistic records, including relevant error cases. For published APIs, install the **linked webservices plugin** generated with the component, enable it using `extension_enable_plugin`, and call `jcb_refresh_tools` with the installed component element, for example `{"component":"com_demo"}`. Browser PHP runs the installed MCP component’s route observer, form inventory and catalogue synchronizer for that component. If a JCB provider also owns native CLI targets, its full refresh belongs on its native host. The native MCP now discovers the registered routes the authenticated Joomla user can access. Search by component in `joomla_actions_search`, describe the returned action and perform the read using the discovered ID.
5. Return to the maintained JCB definition for lasting corrections. Recompile and rerun the checks. Use `site_export({"format":"bundle"})` when delivering the full site. Verify the installed component and generated API after using `site_restore`. To replace an attached site explicitly, pass the exact `replaceWorkspaceId` returned as `workspaceId` by `workspace_attach` along with the archive ID. Complete-site archives can contain private Joomla credentials.

The repository's `node test/jcb-live.mjs` acceptance scenario runs the actual stdio client, reads the packaged skill, changes the seeded Demo J6 component version and its required title field length through their native models, compiles the new version, verifies the transferred ZIPs, installs the component and webservices plugin, checks the installed form has the authored length, reads a country through the generated API and checks that same record after a complete-site restore. The hosted Chromium and Desktop attachment checks reuse this scenario on disposable owner profiles. The fresh component check in `test/fresh-notes-live.mjs` creates a Notes component with a source-traced PHP hook, locates that hook and its originating JCB record in installed administrator code, and exercises the generated form. Use `deployment_discover` and `deployment_capture` to capture existing native records and related definitions as reusable configuration overlays.
