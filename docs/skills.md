# Canonical JoomEngine Skills

The npm package ships a complete offline copy of the JoomEngine Skills distribution. When a client lists prompts, reads or searches Skills, or requests their status, its MCP server checks the canonical repository's default branch. It downloads changes from GitHub at the resolved commit, validates the complete archive and its registered paths, and activates the whole revision. An installed MCP receives new Skills, modules, workflows, examples, scripts and assets without a new npm installation. Resources contain the upstream bytes and preserve relative links. [Canonical distribution](https://github.com/joomengine/skills)

- Call `skills_capabilities` for the operations actually enabled by this host, their accepted actions and their canonical guide URIs. Pass `capability` to select a topic. The result expands registered JCB modules automatically and reports any tool lacking a canonical route. The [upstream capability registry](https://github.com/joomengine/skills/blob/main/registries/playground-mcp.json) owns these relationships.
- Start at `joomengine://skills/SKILL.md`. `skills_list` and `skills_read` expose the same resources to tool-only clients. `skills_search` searches paths, document titles and text across the entire distribution.
- `prompts/list` includes every entry in `registries/skills.json` and Markdown guide under a `workflows/` directory. The build, verification and delivery prompt names from 0.1.0 remain available. Modules retain their own scope, validation status and references in `joomengine://skills/registries/modules.json`.
- `skills_status` reports the bundled, active and last observed upstream revisions, cache status and any refresh error. `{"refresh":true}` forces a new check. Under ordinary use, checks happen at most once every 15 minutes per running process. When any session observes a new revision, connected MCP clients receive both `notifications/resources/list_changed` and `notifications/prompts/list_changed` so they can refresh their catalogs. If a revision changes during pagination, restart the listing using the new revision's cursor.
- Updates resolve the default branch through GitHub's public Git advertisement on `github.com`, independently of the anonymous API quota. An API fallback on `api.github.com` handles networks that block Git traffic. Archives come from `codeload.github.com` at the resolved commit. Verified archives are cached under `$XDG_CACHE_HOME/joomengine-mcp/skills` or the user's `.cache/joomengine-mcp/skills` directory. Set `JOOMENGINE_SKILLS_CACHE` to choose another directory. Set `JOOMENGINE_SKILLS_OFFLINE=1` to use the most recent cached snapshot or the bundled distribution. A failed download leaves the previous snapshot usable.
- The **Verify canonical Skills synchronization** workflow compares every resource of the installed npm server against its upstream Git blob and confirms every registered skill has an MCP prompt. With all optional host tools enabled, it checks that every exact tool name and prefix in the canonical registry matches an advertised tool in its assigned group. The check runs on pull requests, on demand and every six hours. New executable platform capabilities require an implementation in the corresponding runtime/provider and an acceptance test through the installed MCP.

The canonical [workspace guide](https://github.com/joomengine/skills/blob/main/testing/playground/agent-connections.md) explains how the cloud browser, existing Firefox/Chromium sites, JoomEngine Desktop and each Joomla provider relate to the JCB workflow.
